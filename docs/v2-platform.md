# Learn to Build & Open Creator Platform

## Inventory and decisions
- Next.js 14 App Router, TypeScript, static export for GitHub Pages. No server routes or secrets inside the exported site. Existing Campus /learn/, /create/ bakery, DOM story board, legacy free studio, Read/Sing, course collections, official /moli-cutout.png and educator photographs stay intact. The public homepage was not redesigned.
- The bakery's device-local exercise state is not evidence for cloud rewards. The new room is another **DOM-based 2D scene**, with native buttons, percentage coordinates and a single scene array for Build and Play. No canvas dependency or 3D engine was added. Guest official-art rooms work without a backend. Only server-scored activities can create cloud collectibles.
- Supabase Auth + the existing explorers and guardian_preferences define family ownership. An active Explorer with permission to save is required for cloud worlds and practice. Artwork sharing to the private room needs its own opt-in; AI also needs guardian AI permission. A guardian can select an Explorer and erase private room data in /family/. Local guest rooms are not cloud backups or private from other users of that browser.
- Existing /explore/ catalog is preserved. Published external works use separate reviewed records, not fabricated course rows. Channels: /teach/share/, /creators/, /staff/review/. There is no learner inbox or community upload feed. Creator eligibility is a reviewed profile, not a self-declared teacher role. Young creator eligibility/parental authorization must be checked by a human before acceptance. Staff access uses trusted Supabase app_metadata.moli_admin; never user_metadata.
- Creator Moli V1 is integrated from its isolated feature commit. Its private notebooks, explicit confirmations and adult invitation gate are unchanged. Saved concepts can be brought into the independent submission form by ID with owner checks; never auto-submit or convert an external presentation into a mandatory course. The child agent has separate prompts, consent checks and a bounded provider adapter; it cannot call the adult tools.
- New work: reviewed objective → activity → retry-safe score → immutable collectible; private art library and original room scene; creator eligibility → private draft → independent human review → approval → explicit publication → learner resource opening. Reports and recognition nominations are administrative records, not payouts.

## Trying the flows
1. /create/ → Build my world. Place free objects immediately; drag, move using keyboard sliders, resize, rotate, duplicate, reorder, undo/redo, zoom/pan. Save and open Play. Moli, books and stars have an interaction; stars can play a short original chime on demand.
2. For a connected learning record: use an authenticated guardian with an active Explorer and saving permission. In Family, choose “Open this Explorer’s world”. After **human approval of the native activity**, complete three fruit orders. Submit choices, not a score. The server checks an approved answer key, locks attempts to an Explorer/nonce, records the practised objective, and grants at most one basket. Later mistakes never revoke it. Place the basket; in Play it shows “une pomme”, meaning and a review prompt. Pronunciation is optional only if a local French system voice exists.
3. /teach/share/ → apply with an authentic public profile → independent staff eligibility review → private draft. Choose PDF, PPTX, MP4, image storybook, or HTTPS external resource. Uploads must pass the private processor. Preview the actual attachment, enter learning metadata/rights and submit. Rejected or returned versions can be edited. No identity documents, rights documents or private contacts in the public profile.
4. /staff/review/: inspect the resource outside the app and verify rights, age fit, privacy, learning quality, cultural representation and technical suitability. Mark Under Review, request changes/reject, or approve with checks. **Publish** is separate and requires a different account than the author. The published item then appears in /explore/ and /creators/?id=<creator-id>. Opening an external resource is recorded as a visit only when eligible; never completion. A flagged published item can be archived.
5. Recognition only records nominations/programs for staff review. Optional amount, currency, agreement and payment metadata do not create entitlement or trigger a financial transaction.

## Staging setup (not applied automatically)
Use an isolated Supabase staging project and the repo's prior Auth/profiles, families.sql, collections.sql and learning-library.sql foundations. Do not run against production by accident.
- Apply creator-moli.sql (if not already applied), then **learn-build-platform.sql → open-publishing.sql → platform-admin.sql**, once, as the migration owner. These are versioned, transaction-wrapped additions, not rerunnable seed scripts. Storage must already exist. The new private bucket has an explicit restrictive policy for anon/authenticated, even alongside permissive older policies. Review the entire deployment's grants, backup and retention procedures.
- Configure NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY together at build time to select staging. Use a publishable/anon key only. With neither set, the original site's existing public configuration is retained. Never put service role, worker or model secrets in public settings.
- Deploy platform-media, world-moli and (if needed) creator-moli to that project. The handlers authenticate server-side; platform-media's open action additionally admits anonymous readers **only for published resources**. Configure gateway JWT verification appropriate to the project's signing scheme (for newer keys use --no-verify-jwt on handlers that perform their own getUser/ownership checks). SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are Edge secrets, not browser configuration. Keep profiles/requests isolated; grant only vetted accounts staff admin or creator_moli_adult app metadata through trusted admin tooling.
- Media worker: run npm ci in services/platform-media. Use an isolated non-root container/VM with updated clamd + clamdscan, Poppler pdfinfo and ffprobe installed, fresh signatures, CPU/time/memory/disk limits and a private authenticated TLS reverse proxy to the loopback Node service. Set MEDIA_WORKER_TOKEN (at least 32 random characters) on that service and the Edge host; set MEDIA_WORKER_URL on Edge. npm start runs the worker. Do not expose its port publicly. It scans before storage, bounds file size/resolution, rejects malformed PPTX packages and active content indicators, re-encodes images to WebP and makes thumbnails without metadata. This is a processing gate, **not a claim all files are safe**. Quota/scan failures must stay fail-closed. Use periodic cleanup of orphaned private objects and inactive drafts, and verify real scanner/PDF/video processing on staging before inviting children.
- Model: DEEPSEEK_KEY on the Edge host; optional CREATOR_MOLI_MODEL / WORLD_MOLI_MODEL. No client-side LLM key. Image generation is off without MOLI_IMAGE_PROVIDER_URL, optional MOLI_IMAGE_PROVIDER_TOKEN and the worker. The trusted server provider adapter contract is POST JSON {prompt,policy} → {mime,data:base64,safeForChildren:true}. No arbitrary remote image URL fetches. Providers need privacy/safety/retention and cost review; at most three generation requests per Explorer/day. A generated preview is NOT a saved asset. User confirmation includes a short-lived, owner/Explorer/content-bound HMAC receipt. Saved originals/thumbnails remain private.
- Approve the fixed French apple activity via the admin Content Review panel only after a qualified human has checked it. The migration deliberately seeds it **inactive**. A local integration fixture explicitly approves its synthetic activity for tests.

## Reproducible verification
Standard: npm ci, npm run build, npx tsc --noEmit, npx tsc --noEmit -p scripts/edge-test/v2-check.json. Existing library, story-pilot, vocab, games, ingest, bakery, immersive, creator and mocked Edge tests remain available.
Separate QA dependencies (never shipped to children): install @electric-sql/pglite@0.5.15 and playwright@1.62.1 in a temporary QA prefix, set NODE_PATH to its node_modules, have Chrome installed. Install the worker's deps separately. For browser tests, serve **out/** with python3 -m http.server 3022 --bind 127.0.0.1 --directory out.
- node scripts/test-platform-sql.cjs: actual PostgreSQL semantics via PGlite. Checks private RLS, denial of direct storage access under a legacy permissive policy, inaccessible foreign worlds, revision conflicts, retries, non-revocation, no user award writes, creator self-approval denial, explicit review/publication and rejection of non-HTTPS resources.
- npm --prefix services/platform-media test and node scripts/test-platform-media.cjs: actual Sharp decode/re-encode, thumbnail/metadata, wrong signatures, scanner failure, owner isolation, consent off, disabled provider, invalid preview tickets. A scanner callback and private object store are test doubles. No real malware was used.
- node scripts/test-platform-browser.cjs: acceptance A/B in the real UI with the real SQL RPCs/RLS and media handler, synthetic JWT identity and local file storage/scanner doubles. The test creator shares an original one-page PDF; a distinct staff account reviews and publishes; a visitor opens the file and profile. No synthetic creator or submission is deployed.
- node scripts/test-world-browser.cjs: phone/desktop free editor and Play round-trip. node scripts/test-world-moli.cjs: guardian permission, bounded context, forbidden reward proposal ignored, no automatic world mutation, no model call after revocation. npm run test:creator includes Test C's Ukrainian presentation and intent/context checks with a stub model; scripts/eval-creator-moli.cjs is opt-in staging evaluation, not an assertion of live model quality.

## Explicit limits
No new production migration, function deployment, provider purchase, verified creator, or reviewer assignment is performed by this branch. Real provider quality, cloud transport limits, production ClamAV, large video playback and jurisdiction-specific child privacy/legal review require staging/human sign-off. No public upload URL or private source library is exported. Private resource viewing uses short-lived signed URLs opened separately (no parent-window access). External destinations can change and need periodic human re-review. Cross-device world sync applies only to authorized Explorer worlds, not guest rooms. Direct artwork authoring is optional and consent-gated.
Interactive HTML packages, external AI agents, public child social features, contracts, award amounts and automated payouts are **not enabled**. An isolated origin, CSP, sandbox/quotas, dedicated integration review and published legal/program terms are prerequisites for any later expansion. The site intentionally does not execute untrusted code in MoliVerse pages.
